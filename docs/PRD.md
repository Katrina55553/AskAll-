# AskAll — Web 端多 AI 聚合代理工具 产品需求文档 (PRD)

- 版本：1.0
- 状态：草稿待评审
- 依据：`askall-web-ai-aggregator-plan.md`（v5）

## 1. 产品概述
AskAll 是一个 Web 端工具：用户在网页输入问题（可附带多张图片），从 **ChatALL 全部约 66 个 bot** 中勾选 1–5 个，一键并行提问。后端复用各 AI 网页版内部 API / API Key，SSE 流式解析，拿回各 AI 回答后，再由指定"汇总 AI"自动生成最佳答案。**汇总上下文超限时自动分多次**。结果实时展示并存入历史记录，支持注册/登录与按日期分组的历史。

## 2. 背景与目标
- **背景**：用户需同时对比多个 AI 对同一问题的回答，并自动汇总出最佳答案，避免逐个访问各 AI 网页/客户端。
- **目标**：
  1. 单网页完成"多 AI 并行提问 + 自动汇总"。
  2. 复用 ChatALL bot 逆向能力，覆盖约 66 个 AI。
  3. 支持凭据管理（Cookie / API Key），历史记录与用户体系。
- **非目标**：不做多轮对话、不做 AI 对话管理后台、不做移动端适配。

## 3. 目标用户
- 需要多 AI 对比并获取综合答案的个人用户。
- 单机/本地部署使用为主，不面向大规模多用户公网服务。

## 4. 功能需求 (FR)

### FR-1 用户认证
- 注册（用户名 + 密码）、登录、获取当前用户信息。
- 密码 bcrypt 加密存储；登录签发 JWT（有效期 7 天），前端存 localStorage。
- 未登录访问受保护接口返回 401。

### FR-2 提问与图片上传
- 文本框输入问题（必填）。
- 支持上传多张图片，仅发送给支持图片的 bot（`supportsImage`），其余忽略并提示。
- 图片做大小/类型校验与编码。

### FR-3 多 AI 选择
- 展示全部约 66 个 bot，按 ChatALL 标签分组：**免费 / 付费 / API / 国产**（四组折叠面板）。
- 复选框勾选，最多选择 **5 个**，超限提示。
- 另设"汇总 AI"下拉（默认 ChatGPT，可改任意 66 个之一），需已配置凭据。

### FR-4 并行提问与实时进度
- 提交后并行发起各 bot 提问（`Promise.allSettled`）。
- 通过 **SSE** 实时推送每个 bot 状态：等待中 → 回答中 → 已完成，先完成先显示。

### FR-5 汇总（含智能分多次）
- 所有回答就绪后，由汇总 AI 生成最佳答案。
- 按汇总 bot 的 `contextWindow` 估算总 Token（中文约 0.5~0.6 token/字）。
- 若总 Token ≤ 预算（contextWindow×0.8）：单次汇总。
- 若超限：**分层分多次**——先分块各出要点，再合并要点出最终答案，轮次自适应。
- 前端标注汇总轮次。

### FR-6 凭据管理
- 每 bot 一个 JSON 文件（`credentials/{botId}.json`）。
- 网页版 bot：粘贴/校验/清空 **Cookie**。
- API 型 bot：填写/校验/清空 **API Key**。
- 展示各 bot 可用状态。

### FR-7 历史记录
- 按用户存储：问题、图片、各 AI 回答(JSON)、汇总结果、时间。
- 按日期分组列表，点击展开详情，删除（二次确认）。

### FR-8 中英双语
- 界面支持 zh-CN / en-US，语言可切换。

## 5. 非功能需求 (NFR)

### NFR-1 兼容性
- 后端 Node.js ≥ 18（LTS）；前端 Vite + Vue3。
- 单服务器架构：Express 同时提供 API 与托管前端静态资源。

### NFR-2 性能
- 并行提问，SSE 实时推送；失败 bot 降级不阻塞整体。

### NFR-3 安全
- 凭据文件不落库，仅存本地 `credentials/`（gitignore）；JWT 鉴权。
- 数据库 SQLite（better-sqlite3），单机数据。

### NFR-4 可维护性
- 复用 ChatALL bot 层，仅做最小改动；逆向接口在 bot 文件内集中维护。

## 6. 数据模型
- `users`: id, username(unique), password_hash, created_at。
- `history_records`: id, user_id, question, images(JSON), summary, created_at。
- `answer_items`: id, record_id, bot_id, bot_name, status, answer, error, duration_ms。

## 7. 页面与交互
| 页面 | 说明 |
| --- | --- |
| 登录/注册 | 表单 + 语言切换 |
| Ask 主页面 | 输入区（文本+图片）、AI 选择区分组 + "已选 x/5"、汇总 AI 下拉、发送按钮（防重复） |
| 凭据管理 | 66 个 bot 折叠面板，粘贴/校验/清空凭据 |
| 进度区 | 每 bot 一行状态，先完成先显示 |
| 结果区 | 汇总结果（默认展开，分多次标注轮次）+ 各 AI 原始回答可折叠 |
| 历史页 | 按日期分组，展开详情/删除 |

## 8. 验收标准
1. 注册/登录可用，未登录访问受保护接口返回 401。
2. `/api/bots` 返回约 66 个 bot（含标签/凭据类型）。
3. 选 2 个已配置 bot（一个 Cookie 型 + 一个 API 型）提交问题，SSE 进度流与汇总结果正确生成。
4. 凭据粘贴/校验/清空可用。
5. 汇总超限时触发"分多次"路径，轮次与最终答案正确。
6. `npm run build` 后访问根路径可见前端页面。
7. 历史记录落库，历史页可展开/删除。
8. 界面中英双语可切换。

## 9. 设计决策记录 (ADR)
- **汇总 AI 采用官方 API**：为避免网页版逆向的字符上限、风控与维护成本，汇总 AI 优先走官方 API；默认可选 **通义千问 3.6 Flash** 等具免费额度的 API 服务。该决策源自前期架构评审（切换到 API 改动成本最低、收益最大）。
- **凭据双类型**：网页版存 Cookie、API 型存 API Key，独立 JSON 文件便于备份。
- **上下文超限分多次**：分层策略，轮次按汇总 bot 的 contextWindow 动态计算。

## 10. 风险与开放问题
- 逆向接口随站点改版失效，需集中维护；部分站点有 Cloudflare/风控、签名校验。
- 部分 bot 因反爬/无中国大陆访问可能不可用，按失败降级处理。
- 汇总多轮消耗额外请求次数与账号配额，前端需标注轮次。
- 开放问题：汇总 AI 默认选型（ChatGPT vs 通义千问 3.6 Flash）待用户确认。
